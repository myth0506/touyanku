# 投研库：AI 驱动的个人财报分析系统

> 用 Claude Code + Obsidian 搭建你的私人投研助理，把「知道重要但做不到」的财报分析变成两分钟完成的标准动作。

---

## 一、为什么要自己搭这套系统？

今年年初，第一次买入了微软。

逻辑很清晰：Azure 高速增长，OpenAI 加持，Copilot 全线嵌入 Office，年初跌了不少有安全边际。但买入之后股价继续往下，一个问题开始在脑子里转：**到底是情绪导致的短期下跌，还是基本面出了问题？**

要回答这个问题，只有一条路：翻财报。然后就傻眼了——每份 10-Q 将近 100 页，年报 10-K 接近 150 页，全英文，充斥着会计术语。普通投资者面前有三道门槛：**看不懂**（「递延所得税资产」「商誉减值」，大脑自动省电）；**来不及**（MD&A、财务报表、电话会纪要三份材料交叉比对，等你看完市场早跑在前面了）；**没积累**（每次都从头开始，看不出趋势，每次都像第一次一样茫然）。

这三道门槛叠在一起，让财报分析成了一件「知道重要、但做不到」的事。

**而这恰恰是 AI 工具最擅长解决的问题。** Obsidian + Claude Code 这套组合，本质上是给你搭了一个私人投研助理——你不需要懂会计，不需要逐页翻报告，把文件丢进去，两分钟后一份结构清晰的分析笔记就出现在知识库里，和上一个季度自动关联，一眼看出数据在往哪个方向变化。

这才是普通投资者在 AI 时代应该有的工具配置。

下面，我来一步步告诉你怎么搭。

## 二、系统架构总览

动手之前，先花两分钟理解整体架构，能少走很多弯路。

### 2.1 整体分层设计

这套系统分为三层：**数据层**存放原始财报文件，**分析层**存放 AI 生成的笔记，**汇总层**聚合每家公司的长期研究结论。三层各司其职，互不干扰。

```
【数据层】原始财报文件（官方 PDF、Excel、Word、PPT）
        ↓
【处理层】Claude Code（AI 分析引擎）
    ├── 投研分析 Skill    → 定义分析框架、提取逻辑、输出格式
    └── batch.py          → 批量调度：扫描目录、按顺序触发 Skill
        ↓
【分析层 + 汇总层】Obsidian Vault（本地知识库）
```

### 2.3 核心组件说明

**Claude Code** 是这套系统的大脑，但你不需要会写代码。你只需要用自然语言告诉它你想要什么，它会帮你写脚本、调试报错、迭代优化。把它理解为一个随时待命的程序员助手。

**Obsidian** 是这套系统的记忆。所有数据都在本地，不依赖任何云服务，不会因为某个平台关闭而丢失你多年积累的研究成果。

**Python 脚本** 是连接两者的管道，由 Claude Code 生成和维护，你不需要理解代码细节，只需要能运行它。

## 三、环境准备：从零开始安装

### 3.1 安装 Obsidian 并搭建 Vault 结构

前往 [obsidian](https://obsidian.md) 下载对应系统的安装包（支持 Windows、macOS、Linux）。安装后打开，选择「新建 Vault」，建议命名为 `投研库`，路径选择一个固定且好记的位置，例如：

- macOS：`/Users/你的用户名/Documents/投研库`
- Windows：`C:\Users\你的用户名\Documents\投研库`

Vault 创建好后，在 Obsidian 左侧文件栏中，手动创建上面第 2.2 节中的文件夹结构（右键点击空白处 → 新建文件夹）。

然后把你已有的原始财报文件，按公司整理后放入 `原始数据/公司名/季度或年份/` 目录下。以微软为例，之前按 `FYxx-Qx-Asset-Package` 命名的文件夹直接改名为 `FY2026-Q1` 这样的格式放进去即可。

### 3.2 安装 Claude Code

Claude Code 需要 Node.js 运行环境。首先确认你的电脑是否已安装：

```bash
node --version
```

如果提示找不到命令，前往 [nodejs.org](https://nodejs.org) 下载 LTS 版本（当前为 v20.x）安装。

安装好 Node.js 后，在终端运行：

```bash
npm install -g @anthropic-ai/claude-code
```

安装完成后，运行 `claude` 启动。

### 3.3 安装 Python 和依赖库

确认 Python 已安装（3.8 以上版本）：

```bash
python --version
```

然后安装批量调度脚本所需的依赖库：

```bash
pip install python-dotenv
```

这套方案里 Python 脚本只做目录扫描和任务调度，不做任何文件解析，所以依赖极少。文件读取和分析全部交给 Claude Code 的投研分析 Skill 处理，不需要在本地安装 pymupdf、python-docx 这些解析库。

## 四、创建投研分析 Skill

这是整套系统最核心的部分。传统做法是写一堆 Python 脚本来驱动分析，但在 Claude Code 环境下有更优雅的方式——**用 Skill 封装分析方法论，让 Claude Code 本身成为执行引擎**。

Skill 和 Python 脚本的分工非常清晰：

| 维度 | Skill | Python 脚本 |
|---|---|---|
| 负责什么 | 「怎么分析」：分析框架、关注维度、输出格式 | 「批量跑」：目录扫描、任务调度、进度记录 |
| 灵活性 | 随时用自然语言调整分析角度 | 逻辑写死，改动需要修改代码 |
| 跨会话复用 | ✅ 装一次，永久生效 | ❌ 每次要手动运行 |
| 批量处理 | ❌ 需要人逐个触发 | ✅ 自动跑完不用管 |

所以最终的架构是：**Skill 定义方法论，Python 脚本负责批量调度**。

### 4.1 创建投研分析 Skill

在投研库根目录下新建文件 `.claude/skills/投研分析/SKILL.md`：

```markdown
---

name: 投研分析

description: >
  微软等美股公司季度财报分析。当用户说「分析财报」「解读这个季度」
  「读一下 FY26Q1」时触发。输入一个季度资产包目录路径，自动读取
  其中所有文件，生成结构化的 Obsidian 分析笔记。

triggers:
  - 分析财报
  - 解读季报
  - 分析这个季度
  - 读一下
---
## 文件读取优先级

收到季度目录路径后，按以下优先级读取目录内文件：

| 文件特征 | 内容 | 优先级 |
|---|---|---|
| 文件名含 10Q 或 10K（.docx） | 完整财务数据、MD&A | ★★★ 最重要 |
| 文件名含 Transcript 或 EarningsCall（.docx） | 电话会纪要，含管理层问答 | ★★★ 最重要 |
| 文件名含 KPI（.xlsx） | 关键运营指标，结构化数字 | ★★ 重要 |
| 文件名含 PressRelease（.docx） | 新闻稿，精炼的核心摘要 | ★★ 重要 |
| 文件名含 Slides 或 Outlook（.pptx） | 管理层展示材料 | ★ 补充参考 |

文件名模糊匹配，不区分大小写。找不到某类文件时跳过，不报错。

## 提取内容清单
综合读取到的所有文件，提取以下信息：

**基本信息**
- 公司名称、股票代码、财年、季度

**财务数据**（优先从 KPI.xlsx 读取，其次从 10Q.docx）
- 营业收入（当期、上期、同比%）
- 净利润（当期、上期、同比%）
- 毛利率、净利率
- 经营现金流
- 资本开支（CapEx）及同比变化
- 主要业务线收入拆分（如 Azure、Office Commercial、LinkedIn、Gaming）

**管理层信息**（优先从 Transcript 提取）
- 管理层强调的 3 个核心战略重点
- 管理层披露的 3 个主要风险
- 下一季度业绩指引（Guidance），包含具体数字区间
- 本期相比上期最值得关注的 1-2 个变化

## 输出规则
1. 读取 `./模板/财报分析模板.md`，将提取结果填入模板
2. **笔记保存路径**：`/Users/xiekai/Documents/投研库/财报分析/{公司名}/{股票代码}_{财年季度}.md`
   - **必须按公司区分子目录**，不同公司的分析文件隔离存放
   - **文件名必须标记季度**，格式：`股票代码_财年季度.md`
   - 示例：
     - 微软 FY26Q1 → `/Users/xiekai/Documents/投研库/财报分析/微软/MSFT_FY26Q1.md`
     - 谷歌 FY26Q1 → `/Users/xiekai/Documents/投研库/财报分析/谷歌/GOOGL_FY26Q1.md`
     - 亚马逊 FY26Q1 → `/Users/xiekai/Documents/投研库/财报分析/亚马逊/AMZN_FY26Q1.md`
3. 分析前检查目标目录是否存在，不存在则自动创建：
   `mkdir -p /Users/xiekai/Documents/投研库/财报分析/{公司名}/`
4. 检查 `/Users/xiekai/Documents/投研库/公司主页/{公司名}.md` 是否存在：
   - 不存在：从 `./模板/公司主页模板.md` 新建
   - 已存在：在「财报记录」章节追加本次笔记链接
5. 笔记中记录原始文件的来源路径，便于跳转查阅
6. 完成后输出摘要：生成了哪个笔记、路径、是否新建了公司主页

## 分析重点提示
- CapEx 同比变化超过 ±30%，在笔记「本期核心变化」章节单独标注原因
- Guidance 必须独立成节，包含具体数字，不能只写「管理层表示乐观」
- Azure 增速是微软估值的核心变量，需与上期数字并排呈现
- 经营现金流/净利润比值偏离 1 超过 20%，需在盈利质量章节说明原因
```

### 4.3 调整和迭代 Skill

Skill 的核心优势是可以随时用自然语言优化分析框架，不需要动代码。几个典型的迭代场景：

**调整关注维度**：直接在 SKILL.md 里补充，比如「分析师问答中被追问超过两次的话题，单独列出」。

**适配新公司**：苹果、英伟达的财报结构和微软不同，可以给每家公司单独建一个 Skill，或者在现有 Skill 里加条件分支：「如果是英伟达，重点提取数据中心收入和毛利率；如果是苹果，重点提取各产品线和服务收入」。

**深化分析角度**：积累几个季度后，可以在 Skill 里加入「与过去四个季度的同指标对比，判断趋势方向」，让每次分析自动包含纵向视角。

## 六、安装关键 Obsidian 插件

打开 Obsidian，进入「设置」→「第三方插件」→ 关闭安全模式 → 「浏览」，搜索并安装以下插件：

**Dataview**（必装）
让你用类 SQL 语法查询笔记库。安装后，公司主页里的财报汇总表、行业对比页面都依赖它运行。安装完记得在插件设置里开启「Enable JavaScript Queries」和「Enable Inline Queries」。

**Templater**（必装）
比 Obsidian 内置的模板功能强大得多，支持动态日期、文件名变量、JavaScript 函数等。我们的模板里用到了 `{{date}}` 等动态变量，都需要 Templater 才能正确填充。

**Obsidian Git**（强烈推荐）
自动将整个 Vault 备份到 Git 仓库（本地或 GitHub）。财报分析笔记是你多年积累的研究资产，一次硬盘故障就可能全部丢失。这个插件配置好后，每天自动提交，无需手动操作。

**Charts View**（推荐）
在笔记里直接渲染折线图、柱状图。配合 Dataview 的数据，可以把多期营收趋势、毛利率变化等直接可视化，不需要另开 Excel。

**Calendar**（可选）
在 Obsidian 里显示日历视图，财报分析笔记按日期展示，方便回顾某个时间段做了哪些分析。

在 Claude Code 中输入：

```
在 ./脚本/ 目录下创建 batch.py，实现：
1. 扫描 ./原始数据/指定公司/ 下所有季度目录（格式如 FY2026-Q1）
2. 检查每个季度是否已在 ./财报分析/公司名/ 中有对应笔记，跳过已处理的
3. 对未处理的季度，按时间顺序依次调用 claude 命令行，
   传入「分析一下 原始数据/公司名/季度目录/」作为指令
4. 每个季度处理完后记录状态，生成 ./待办/batch_report.md：
   - 成功处理的季度列表（附生成笔记路径）
   - 失败的季度列表（附错误原因）
   - 跳过的季度列表（已处理过）
5. 支持 --dry-run 参数，只列出待处理队列不实际执行
6. 支持 --company 参数指定公司，不填则处理 ./原始数据/ 下所有公司

注意：分析逻辑不在这个脚本里，全部交给 Claude Code 的投研分析 Skill 处理。
这个脚本只做目录扫描和任务调度。
```

### 8.2 批量归档微软十年历史

脚本创建好后，工作流：

```bash
# 先预演，确认待处理队列
python 脚本/batch.py --company 微软 --dry-run

# 输出类似：
# 待处理：45 个季度
# FY2015-Q2, FY2015-Q3, FY2015-Q4 ... FY2026-Q1
# 已跳过：0 个（无已有笔记）

# 确认无误后正式运行
python 脚本/batch.py --company 微软
```

**使用示例**

```bash
# 只跑 2024 财年
python batch.py --company 微软 --year 2024

# 只跑 2023-2025 的 Q1

# 只跑偶数季度（Q2、Q4）

```

微软从 FY2015 到现在大约 45 个季度，每个季度处理约 1-2 分钟，全部跑完大概需要 1-1.5 小时。跑完之后，`财报分析/微软/` 目录下就有了完整的历史档案，`公司主页/微软.md` 里自动汇聚了所有季度的链接和核心数字。
